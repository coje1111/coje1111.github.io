## 자동완성으로 작성한 코드를 다시 읽어보기

여러 숫자를 입력받다가 `-1`이 나오면 종료하고, 입력한 숫자의 합계와 평균을 출력하는 문제를 풀었다. 예시 입력 `1, 2, 3, 4, -1`에서는 합계 `10`, 평균 `2.5`가 나왔다.

다만 자동완성의 도움으로 코드를 작성해, 각 줄이 왜 필요한지 스스로 설명하기는 어려웠다. 풀이를 하나씩 다시 읽고, 이후에는 같은 반복문을 조건식 한 줄로 줄일 수 있는 원리도 질문했다.

## 반복하면서 기억할 것은 합계와 개수

문제의 순서는 다음과 같다.

1. 숫자를 하나 읽는다.
2. `-1`이면 반복을 끝낸다.
3. 다른 숫자라면 합계에 더하고 개수를 1 늘린다.
4. 반복이 끝나면 합계와 평균을 출력한다.

평균은 합계를 개수로 나누므로, 합계뿐 아니라 입력 개수도 저장해야 한다.

```java
int sum = 0;   // 지금까지 입력한 숫자의 합계
int count = 0; // 지금까지 입력한 숫자의 개수

while (true) {
    int input = scanner.nextInt(); // 이번 숫자 하나를 읽는다.

    if (input == -1) {
        break; // 종료 신호는 합계와 개수에 포함하지 않는다.
    }

    sum += input; // sum = sum + input;
    count++;      // count = count + 1;
}
```

`scanner`는 앞에서 만든 `Scanner` 변수다. `sum`과 `count`는 반복문 밖에서 선언하므로 반복마다 값이 이어서 쌓인다. 반면 `input`은 이번에 읽은 숫자를 담는다.

| 입력 | sum | count | 처리 |
|---|---:|---:|---|
| 시작 전 | 0 | 0 | 아직 입력 없음 |
| 1 | 1 | 1 | 더하고 개수 증가 |
| 2 | 3 | 2 | 더하고 개수 증가 |
| 3 | 6 | 3 | 더하고 개수 증가 |
| 4 | 10 | 4 | 더하고 개수 증가 |
| -1 | 10 | 4 | 더하기 전에 종료 |

`-1` 확인을 먼저 하는 이유는 종료 신호를 계산에서 제외하기 위해서다. 합계와 개수부터 바꾸면 `-1`도 입력 데이터로 포함된다.

## 평균 계산과 숫자를 하나도 입력하지 않은 경우

정수끼리 나누면 소수 부분이 버려진다. 평균을 소수까지 구하려면 나누기 전에 한쪽을 `double`로 바꿔야 한다.

```java
10 / 4           // 결과: 2
(double) 10 / 4  // 결과: 2.5
(double) (10 / 4) // 결과: 2.0 — 정수 나눗셈이 먼저 끝났다.
```

`(double) sum`은 이번 계산에서 `sum`의 값을 소수를 표현할 수 있는 자료형으로 변환하는 것이며, 변수 `sum` 자체의 자료형이 바뀌는 것은 아니다.

여기서 “처음부터 `-1`을 입력하면?”이라는 경우도 생각해봤다. 그때는 `sum`과 `count` 모두 `0`이므로 평균을 계산할 수 없다.

```java
System.out.println("입력한 숫자들의 합계: " + sum);

if (count > 0) {
    double average = (double) sum / count;
    System.out.println("입력한 숫자들의 평균: " + average);
} else {
    System.out.println("입력한 숫자가 없어 평균을 계산할 수 없습니다.");
}
```

원래 식인 `(double) sum / count`를 그대로 계산하면 이 경우에는 실수 연산 `0.0 / 0`이 되어 `NaN`이 나온다. `NaN`은 정상적인 수로 표현할 수 없는 결과라는 뜻이다. 정수 나눗셈에서 0으로 나눌 때 발생하는 예외와는 다르다.

이번에는 빈 입력에 대한 처리를 보완했다. 문자를 입력한 경우나 합계가 `int`의 범위를 넘는 경우는 별도로 고려할 사항이다.

## while 조건식에 입력과 비교를 함께 쓰는 원리

위 반복문을 다음처럼 줄인 코드를 보고 놀랐다.

```java
int input; // 조건식에서도 사용할 수 있도록 반복문 앞에서 선언한다.

while ((input = scanner.nextInt()) != -1) {
    sum += input;
    count++;
}
```

이 코드는 앞의 `while (true)` 버전을 대체하는 코드이며, `sum`, `count`, `scanner`는 앞에서 준비되어 있어야 한다.

핵심은 **대입식도 결과값을 가진다**는 Java의 성질이다. 다음 괄호 안 식은 입력값을 `input`에 저장하면서, 그 저장한 값 자체를 식의 결과로 내놓는다.

```java
(input = scanner.nextInt())
```

`3`을 입력하면 다음 순서로 처리된다.

1. `scanner.nextInt()`가 `3`을 읽는다.
2. `input`에 `3`을 저장한다.
3. 대입식의 결과 `3`을 이용해 `3 != -1`을 검사한다.
4. 조건이 참이므로 합계와 개수를 갱신한다.

다음 반복에서도 먼저 새 숫자를 읽는다. `-1`을 읽으면 `input`에 저장한 뒤 조건이 거짓이 되어, 반복문 본문에 들어가지 않고 종료한다.

이때 `=`는 값을 저장하는 대입이고, `!=`는 두 값이 다른지 비교하는 연산이다. 안쪽 괄호는 대입식을 먼저 계산해 그 결과를 비교하도록 묶는다.

> 원래 코드: `-1`이면 그만둔다.
>
> 축약 코드: 입력받은 값이 `-1`이 아니면 계속한다.

두 버전은 이 문제에서 같은 입력과 계산 흐름을 가진다. 다만 원래 버전에서 `input`을 반복문 안에 선언했다면, 축약할 때는 조건식에서도 쓸 수 있도록 선언 위치를 밖으로 옮겨야 한다.

## count > 0 검사는 왜 반복문 밖에 둘까?

축약한 `while`문을 배운 뒤, 숫자를 하나도 입력하지 않은 경우를 처리하는 `if (count > 0)`도 그 반복문 안에 넣을 수 있는지 궁금했다.

문법상 안에 넣는 것은 가능하지만, 이 문제는 **모든 입력이 끝난 뒤 최종 합계와 평균을 출력**해야 한다. 따라서 결과 출력과 평균 계산 가능 여부 검사는 반복문 밖에 둔다.

```java
int sum = 0;
int count = 0;
int input;

while ((input = scanner.nextInt()) != -1) {
    sum += input;
    count++;
} // 입력을 마친 뒤 아래 코드로 넘어간다.

System.out.println("입력한 숫자들의 합계: " + sum);

if (count > 0) {
    double average = (double) sum / count;
    System.out.println("입력한 숫자들의 평균: " + average);
} else {
    System.out.println("입력한 숫자가 없어 평균을 계산할 수 없습니다.");
}
```

이 코드에서도 `scanner`는 앞에서 만든 `Scanner` 변수다. 처음부터 `-1`을 입력하면 다음 순서로 동작한다.

```text
-1 입력 → while 조건이 거짓 → 반복문 안에 한 번도 들어가지 않음
→ 반복문 밖에서 count 확인 → 0이므로 평균을 계산할 수 없다는 안내
```

검사 코드를 반복문 안에 두면, 정작 숫자를 하나도 입력하지 않은 상황에서 검사 자체가 실행되지 않는다. 또한 `count++` 뒤에서 검사하면 이미 개수가 1 이상인 상태이므로 빈 입력을 확인할 수 없고, 숫자를 받을 때마다 중간 결과를 출력하게 된다.

이 문제에서는 **반복문 안은 입력과 누적 계산**, **반복문 밖은 최종 결과 출력과 입력 개수 확인**으로 역할을 나누면 이해하기 쉽다. 코드를 줄여도 예외 상황을 처리할 수 있으며, 그 코드가 언제 실행되는지가 중요하다.

## 코드 길이보다 실행 순서를 이해하기

처음에는 이런 축약을 스스로 떠올리는 것이 경험이나 특별한 응용력의 문제인지 궁금했다. 이번에는 대입식이 결과값을 가진다는 문법을 알게 되면서, 입력과 반복 조건을 한 줄로 연결할 수 있었다.

코드를 줄여야 더 좋은 답이 되는 것은 아니다. 처음의 `while (true)`와 `break` 방식도 입력·종료·계산 순서가 잘 드러나는 풀이이다.

다시 풀 때는 먼저 “반복하면서 무엇을 기억해야 하는가?”를 생각한다. 그다음 일반 입력뿐 아니라 숫자 하나만 입력한 경우, 바로 종료한 경우에도 결과가 올바른지 확인한다.

- `1, 2, 3, 4, -1` → 합계 `10`, 평균 `2.5`
- `7, -1` → 합계 `7`, 평균 `7.0`
- `-1` → 합계 `0`, 평균을 계산할 수 없다는 안내
