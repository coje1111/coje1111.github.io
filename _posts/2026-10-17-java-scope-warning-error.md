## 실행은 되는데 왜 커밋 검사가 멈췄을까?

지역 변수의 범위를 공부하면서 프로그램은 정상 실행됐지만, IntelliJ에서 커밋·푸시를 시도할 때 `Commit and push checks failed`와 `1 warning`이 표시된 적이 있다. 처음에는 코드가 실행되는데 왜 오류가 나는지 헷갈렸다.

이번에는 그 사례를 복습하면서, IDE의 코드 검사 경고와 Java 컴파일 오류를 구분해 정리했다.

## if (true)는 실행 오류가 아니라 경고였다

검사 결과를 확인하니 다음 문구가 나왔다.

```text
Condition is always true
```

뜻은 “조건이 항상 참이다”이다. 원인은 다음 코드였다.

```java
if (true) {
    // 항상 실행된다.
}
```

`if`는 조건에 따라 실행 여부를 결정하는데, `true`를 직접 넣으면 항상 실행된다. IntelliJ는 조건 검사가 불필요할 수 있다는 점을 경고한 것이고, Java 문법상 잘못된 코드는 아니었다.

당시 예제는 중괄호 안팎에서 변수를 사용할 수 있는 범위를 보여주려는 코드였다. 따라서 학습 의도를 이해하고 그대로 둘 수 있었다.

## 중괄호 밖에서 x를 사용하면 실제 컴파일 오류가 난다

```java
public class ScopeExample {
    public static void main(String[] args) {
        int m = 10;

        if (true) {
            int x = 20;
            System.out.println("if m = " + m);
            System.out.println("if x = " + x);
        }

        // System.out.println("main x = " + x); // 주석을 풀면 컴파일 오류
        System.out.println("main m = " + m);
    }
}
```

스코프(scope)는 **변수를 사용할 수 있는 범위**다. `m`은 `main` 메서드의 블록 안에서 선언했으므로 선언 뒤의 `if` 안과 밖에서 사용할 수 있다. 반면 `x`는 `if`의 블록 안에서 선언해 그 블록 안에서만 사용할 수 있다.

`if`가 항상 실행되더라도 `x`의 사용 범위가 넓어지는 것은 아니다. 바깥에서 `x`를 출력하는 줄의 주석을 풀면 컴파일러가 그 위치에서 `x`를 찾을 수 없어 실행할 새 프로그램을 만들지 못한다.

## 경고, 컴파일 오류, Git 오류를 나눠 보기

| 구분 | 이번 사례에서의 의미 |
|---|---|
| 코드 검사 경고 | `if (true)`처럼 실행은 가능하지만 확인할 부분이 있다는 IDE의 안내 |
| 컴파일 오류 | 범위 밖의 `x` 사용처럼 Java 규칙에 맞지 않아 컴파일할 수 없는 상태 |
| Git 오류 | 인증 실패나 원격 브랜치 충돌처럼 커밋·푸시 자체의 문제 |

당시에는 Git 푸시가 원격 서버에서 거부된 것이 아니라, **커밋 전 코드 검사에서 경고가 발견되어 진행이 멈춘 상태**였다. 경고 내용을 확인한 뒤, 해당 화면의 `Commit Anyway` 또는 `Commit Anyway and Push…`로 검사 결과를 무시하고 진행할 수 있었다. 다만 경고가 모두 무해한 것은 아니므로 원인을 먼저 읽어야 한다.

## 다시 확인할 때의 기준

1. 프로그램 실행 결과와 커밋 검사 메시지를 따로 확인한다.
2. `warning`이면 어떤 코드에 대한 안내인지 확인한다.
3. 변수 사용 오류라면 선언 위치와 중괄호 범위를 먼저 본다.
4. 커밋 검사를 통과한 뒤에도 푸시가 실패한다면 실제 Git 오류 메시지를 확인한다.

`if (true)`의 경고와 중괄호 밖 `x` 사용 오류는 서로 다른 문제였다. 메시지에 실패라고 적혀 있다는 이유만으로 같은 오류로 생각하지 않고, 어느 단계에서 무엇을 확인하라는 것인지 구분해야 한다.
