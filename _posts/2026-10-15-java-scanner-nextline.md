## 이전에는 괜찮았는데 왜 이번에는 다를까?

이름과 나이를 반복해서 입력받는 예제를 공부하다가, 나이를 읽은 뒤에 있는 `input.nextLine();`이 이해되지 않았다. 나이는 이미 입력받았는데 왜 입력을 한 번 더 읽는지 궁금했다.

이전 예제에서도 숫자를 입력한 뒤 엔터를 눌렀지만 별다른 문제가 없었다. 그래서 엔터가 아직 읽지 않은 상태로 남을 수 있다는 사실을 이번에 처음 알게 되었다.

## 숫자를 읽는 것과 한 줄을 읽는 것은 다르다

나이로 `20`을 입력하고 엔터를 누르면, 프로그램이 읽을 입력을 다음처럼 생각할 수 있다. `[엔터]`는 줄이 끝났다는 표시다.

```text
20[엔터]
```

```java
int age = input.nextInt();
```

`nextInt()`는 숫자 `20`을 읽어 `age`에 저장하지만, 숫자 뒤의 줄바꿈까지 읽지는 않는다.

```text
읽은 값: 20 → age에 저장
남은 입력: [엔터]
```

반면 `nextLine()`은 **현재 위치부터 줄의 나머지를 읽고, 줄을 끝내는 줄바꿈까지 소비한다.** 반환하는 문자열에는 줄바꿈이 포함되지 않는다.

따라서 바로 이름을 읽으면 다음처럼 된다.

```java
int age = input.nextInt();
String name = input.nextLine();
```

`nextLine()`이 남아 있던 엔터를 바로 만나므로, 새로운 이름을 기다리지 않고 빈 문자열 `""`을 돌려준다. 이름과 나이를 받는 반복문에서도 다음 반복의 이름 입력이 같은 영향을 받는다.

## 남은 줄을 한 번 읽어서 넘기기

```java
int age = input.nextInt(); // 나이 숫자를 읽어 저장한다.
input.nextLine();          // 현재 줄의 나머지와 엔터를 처리한다.
```

나이만 입력한 상황이라면 두 번째 줄이 남은 엔터를 소비한다. 이후 이름을 읽는 `nextLine()`은 다음 줄에서 새 입력을 받을 수 있다.

두 번째 줄도 입력을 읽는 메서드다. 다만 읽은 문자열을 변수에 저장하지 않아 결과를 사용하지 않는 것이다. 입력 전체를 비우는 명령은 아니며, 그 줄에 숫자 외의 글자가 남아 있다면 그 글자도 함께 읽어 넘긴다.

## 이전 숫자 입력 예제에서 문제가 없었던 이유

음식 가격과 수량을 받는 예제에서는 `nextInt()`를 연속으로 사용했다.

```java
int foodPrice = input.nextInt();
int foodQuantity = input.nextInt();
```

`nextInt()`는 다음 숫자를 찾을 때 **앞에 있는 공백과 엔터를 건너뛴다.** 그래서 가격 입력 뒤에 엔터가 남아 있어도 수량을 읽는 데 문제가 없었다.

- `nextInt()` 다음에 `nextInt()` → 남은 엔터를 건너뛰고 다음 숫자를 읽는다.
- `nextInt()` 다음에 `nextLine()` → 남은 엔터에서 현재 줄 읽기가 바로 끝날 수 있다.

즉, 이전에도 엔터가 남을 수 있었지만 숫자 입력만 이어져 차이가 드러나지 않았던 것이다.

## 다시 확인하는 방법과 기억할 점

나이만 입력하는 상황에서, 정리용 `input.nextLine();`을 주석 처리한 경우와 다시 넣은 경우를 비교하면 된다. 줄바꿈 처리가 없으면 다음 이름이 빈 문자열이 되고, 넣으면 다음 이름을 입력할 수 있다.

> `nextInt()`는 숫자를 읽는다. `nextLine()`은 현재 줄의 나머지를 읽고 엔터까지 넘긴다.

이번에 헷갈린 이유는 반복문이 복잡해져서만이 아니라, 두 입력 메서드가 읽는 범위가 달랐기 때문이다. 입력이 건너뛰어지는 것처럼 보이면 먼저 직전에 어떤 메서드로 읽었는지 확인한다.
